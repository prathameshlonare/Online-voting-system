| Pattern | What it does | When I'd use it |

## Part 2: The Problem with One-Stage Dockerfiles (15 min)

### The Problem

```dockerfile
FROM node:18
COPY . .
RUN npm install
RUN npm run build
CMD ["npm", "start"]
```

This creates a 1.42GB image because:
- Full node:18 runtime (1.2GB) stays in final image
- Source code + node_modules included
- Root user inside container
- 2-minute rebuilds on every change

### Why This Fails in Production

| Issue | Impact |
|-------|--------|
| 1.42GB image | Slow pulls, ECS task size limits |
| Root user | Security vulnerability |
| No layer caching | 2-min rebuilds in CI/CD |
| Dev server in production | `npm start` runs dev server, not production |

## Part 3: Multi-Stage Builds — 1.4GB → 23MB (25 min)

### The Fix

**docker/Dockerfile.frontend.prod**
```dockerfile
# Stage 1: Build
FROM node:18-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# Stage 2: Runtime
FROM nginx:alpine
RUN adduser -S appuser
COPY --from=builder /app/build /usr/share/nginx/html
USER appuser
```

### How It Works

| Stage | What Happens | Size |
|-------|--------------|------|
| Builder | Installs deps, builds React app | ~1.2GB (temporary) |
| Runtime | Copies only build output to nginx | ~23MB (final) |

### Key Patterns

```dockerfile
# Pattern 1: COPY package*.json first (layer caching)
COPY package*.json ./
RUN npm ci
COPY . .
# Only reinstalls deps if package.json changes

# Pattern 2: npm ci vs npm install
RUN npm ci          # Deterministic, faster, fails on mismatch
# vs
RUN npm install     # Non-deterministic, slower

# Pattern 3: Non-root user
RUN adduser -S appuser
USER appuser
# Container runs unprivileged (security best practice)

# Pattern 4: nginx:alpine base
FROM nginx:alpine   # 23MB vs 1.2GB node image
```

### Try It Now

```bash
cd Online-voting-system

# Build optimized image
docker build -t voting-frontend:optimized -f docker/Dockerfile.frontend.prod .

# Check size
docker images voting-frontend:optimized
# Should show ~23MB

# Run and test
docker run -d -p 3000:80 voting-frontend:optimized
curl http://localhost:3000
# Should load frontend

# Verify non-root
docker exec <container-id> whoami
# Should return: appuser
```

## Part 4: Layer Caching — 2min → 15sec Rebuilds (15 min)

### The Problem

Without layer caching, every code change reinstalls all dependencies:

```dockerfile
# BAD: No layer caching
COPY . .
RUN npm install
# Changes any file → reinstalls all deps (2 min)
```

### The Fix

```dockerfile
# GOOD: Layer caching
COPY package*.json ./
RUN npm ci
COPY . .
# Changes app code → only copies files (15 sec)
# Changes package.json → reinstalls deps (2 min)
```

### How Layer Caching Works

```
Layer 1: COPY package*.json ./     → Cached (unless package.json changes)
Layer 2: RUN npm ci               → Cached (unless package.json changes)
Layer 3: COPY . .                 → Rebuilt (code changed)
Layer 4: RUN npm run build        → Rebuilt (code changed)
```

### Try It Now

```bash
# First build (full)
time docker build -t voting-frontend:v1 -f docker/Dockerfile.frontend.prod .
# ~2 min

# Change a React component (any file in src/)
# Second build (cached)
time docker build -t voting-frontend:v2 -f docker/Dockerfile.frontend.prod .
# ~15 sec (only copies changed files)
```

## Part 5: Security Hardening (15 min)

### The Problem

```dockerfile
# INSECURE: Running as root
FROM node:18
COPY . .
RUN npm install
CMD ["npm", "start"]
# Container runs as root = security vulnerability
```

### The Fix

```dockerfile
# SECURE: Non-root user
FROM node:18-alpine
RUN adduser -S appuser
WORKDIR /app
COPY . .
RUN npm ci
USER appuser
CMD ["npm", "start"]
# Container runs as appuser (non-root)
```

### Security Checklist

| Practice | Why | How |
|----------|-----|-----|
| Non-root user | Prevents container escape | `RUN adduser -S appuser` + `USER appuser` |
| Minimal base image | Reduces attack surface | `alpine` instead of `ubuntu` |
| No secrets in image | Prevents credential leaks | Use env vars or secrets management |
| Scan for vulnerabilities | Find known CVEs | `docker scan voting-frontend` |
| Read-only filesystem | Prevents tampering | `--read-only` flag |

### Try It Now

```bash
# Build with security
docker build -t voting-frontend:secure -f docker/Dockerfile.frontend.prod .

# Verify non-root
docker run -d -p 3000:80 voting-frontend:secure
docker exec <container-id> whoami
# Should return: appuser

# Check user ID
docker exec <container-id> id
# Should show uid=100(appuser) group=100(appuser)
```

## Part 7: Recap (5 min)

### What You Learned

| Pattern | Use Case | My Project |
|---------|----------|------------|
| Multi-stage builds | Small, secure images | 1.4GB → 23MB |
| Layer caching | Fast CI/CD rebuilds | 2min → 15sec |
| `npm ci` | Deterministic installs | All Node.js projects |
| Non-root user | Security best practice | ECS security scan |
| `nginx:alpine` | Minimal runtime | Production frontend |

### The Pattern

When writing production Dockerfiles:
1. **Multi-stage build** — build in Node, ship on nginx
2. **COPY package*.json first** — enable layer caching
3. **Use `npm ci`** — deterministic, faster
4. **Add non-root user** — security best practice
5. **Use minimal base** — alpine over ubuntu
6. **Test size and security** — verify before pushing
