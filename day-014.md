## Part 1: Why This Matters for Online-voting-system (10 min)

Right now, your frontend container can reach DynamoDB directly. In production, that's a security violation — public subnet → database should never happen. Docker networks let you simulate VPC public/private subnets locally.

| Command/Concept | What it does | When I'd use it |
|-----------------|--------------|-----------------|
| `docker network create` | Isolates containers into segments | Every multi-service app |
| `docker network connect` | Adds container to a network | Debugging,临时 access |
| Named volumes | Persists data beyond container lifecycle | Databases, stateful services |
| `-v` flag | Mounts host directory into container | Live code changes |

## Part 2: Docker Networks — VPC Pattern (20 min)

### The Problem

Right now, `docker compose up` puts all services on one default network. Frontend can reach DynamoDB directly. In production, that's a security violation.

### The Fix

Two custom bridge networks mirror VPC public/private subnets:

```
frontend-net (public)     backend-net (private)
┌──────────────┐          ┌──────────────┐
│  frontend    │ ◄─────── │   backend    │ ◄─────── │ dynamodb │
└──────────────┘          └──────────────┘
      │                         │
   Internet                  Internal only
```

### The Command

```bash
# Create networks
docker network create frontend-net
docker network create backend-net

# Connect containers
docker network connect frontend-net voting-frontend-1
docker network connect frontend-net voting-backend-1
docker network connect backend-net voting-backend-1
docker network connect backend-net voting-dynamodb-1
```

### Try It Now

```bash
# Verify networks exist
docker network ls

# Inspect frontend-net
docker network inspect frontend-net

# Test: Frontend CANNOT reach DynamoDB
docker exec voting-frontend-1 nslookup dynamodb
# ** connection timed out ** (correct!)

# Test: Frontend CAN reach backend
docker exec voting-frontend-1 nslookup backend
# ** resolves to private IP ** (correct!)
```

## Part 3: Docker Compose with Networks (15 min)

### The Problem

Running manual `docker network create` commands is tedious. Compose can define networks declaratively.

### The Fix

**docker/docker-compose.yml**
```yaml
version: '3.8'
services:
  frontend:
    build:
      context: ../frontend
      dockerfile: ../docker/Dockerfile.frontend
    ports: ["3000:3000"]
    networks: [frontend-net]
    depends_on: [backend]

  backend:
    build:
      context: ../backend
      dockerfile: ../docker/Dockerfile.backend
    ports: ["4000:4000"]
    networks: [frontend-net, backend-net]
    depends_on: [dynamodb]

  dynamodb:
    image: amazon/dynamodb-local
    ports: ["8000:8000"]
    networks: [backend-net]
    volumes: [voting-db-data]

networks:
  frontend-net:  # public subnet equivalent
  backend-net:   # private subnet equivalent

volumes:
  voting-db-data:
```

### Try It Now

```bash
cd Online-voting-system
docker compose -f docker/docker-compose.yml up -d
# 3 services start in 2 seconds

# Verify networks
docker network ls
# Should show voting-frontend-net and voting-backend-net

# Test isolation
docker exec voting-frontend-1 nslookup dynamodb
# ** connection timed out ** (correct!)
```

## Part 4: Named Volumes — Data Survives Restart (15 min)

### The Problem

`docker compose down` destroyed all votes. Not acceptable for a real app.

### The Fix

Named volume `voting-db-data` mounted to DynamoDB:

```yaml
services:
  dynamodb:
    volumes: [voting-db-data]
volumes:
  voting-db-data:
```

### Try It Now

```bash
# Add 10 votes via frontend
docker compose down          # no -v flag!
docker compose up -d
# Votes still there ✓

# Nuclear option (removes volume):
docker compose down -v       # votes GONE
```

### Exercise 3

1. Inspect volume: `docker volume inspect voting-db-data`
2. Find mountpoint on host: `docker volume inspect voting-db-data --format '{{.Mountpoint}}'`
3. Verify data files exist there

## Part 6: Recap (5 min)

### What You Learned

| Command/Concept | Use Case | My Project |
|-----------------|----------|------------|
| `docker network create` | Security isolation | VPC pattern |
| Custom bridge networks | Public/private subnets | Frontend-net/backend-net |
| Named volumes | Data persistence | DynamoDB votes |
| `docker volume inspect` | Debug storage | Check mount points |
| Compose networks | Declarative networking | Single file definition |

### The Pattern

When containerizing a multi-service app:
1. **Create networks** — frontend-net (public) → backend-net (private)
2. **Assign services** — frontend on public, backend on both, database on private
3. **Add volumes** — named volumes for databases
4. **Test isolation** — verify frontend can't reach database
5. **Test persistence** — verify data survives down/up
